# Setup Harness — 초보자용 프로젝트 세팅 위저드

Claude Code를 처음 쓰는 사람도 **타이핑·전문용어 없이 클릭만으로** 자기 프로젝트에 맞는 `.claude/` 설정을 갖추도록 돕는 대화형 위저드다. 모든 결과물은 **프로젝트 스코프**(이 저장소의 `CLAUDE.md`와 `.claude/`)로 생성되며, 글로벌 `~/.claude/`는 절대 건드리지 않는다.

## 핵심 원칙 (왜 이렇게 하는가)

- **초보자 우선.** 사용자는 `rules`, `frontmatter`, `permissions` 같은 용어를 모를 수 있다. 용어가 처음 등장하면 한 줄로 풀어 설명한다. 사용자가 "이게 뭐예요?"라고 물으면 `references/concepts.md`를 읽고 쉬운 말로 답한다.
- **적응형.** 모든 사람에게 같은 걸 만들지 않는다. 먼저 목표/깊이를 물어, 필요한 만큼만 생성한다. 작게 시작해 나중에 늘리는 게 초보자에게 안전하다.
- **자동 감지로 타이핑 최소화.** 빌드/테스트 명령 같은 건 사용자에게 묻기 전에 프로젝트 파일에서 먼저 추론하고, "이게 맞나요?"로 **확인만** 받는다.
- **무단 변경 금지.** 이미 있는 `CLAUDE.md`·`settings.json`·`rules/`를 절대 덮어쓰지 않는다. 감지해서 보완(append)할지, 그대로 둘지 사용자가 고르게 한다.
- **쓰기 전 미리보기.** 파일을 만들기 직전, 무엇이 어디에 생기는지 트리와 내용을 보여주고 최종 확인을 받는다. 초보자는 이 과정에서 배운다.
- **진행하며 가르치기.** 생성하는 파일마다 "이게 뭔지" 친절한 주석을 넣고, 마지막에 각 파일의 역할과 편집법을 정리해 준다.

## 도구 사용 규칙

- **모든 질문은 `AskUserQuestion` 다지선다로 한다.** 자유 입력을 강요하지 않는다. 각 질문에는 2~4개의 선택지를 주고, 가장 무난한 선택지 라벨 끝에 "(추천)"을 붙여 첫 번째에 둔다.
- 선택지로 표현하기 어려운 값(예: 특정 명령어 문자열)은 자동 감지값을 기본으로 제시하고 "맞음 / 직접 입력"으로 받는다.
- 한 번에 하나의 결정에 집중한다. 질문 폭탄을 피한다.

## 워크플로우

### Step 0 · 환영 + 기존 설정 감지

1. 한두 문장으로 친근하게 인사하고, 이 위저드가 무엇을 해줄지 쉽게 설명한다.
2. 다음을 확인한다: `CLAUDE.md`, `.claude/settings.json`, `.claude/rules/`, `.claude/agents/`, `.claude/skills/`.
3. 기존 설정이 **있으면** `AskUserQuestion`으로 진행 방식을 고르게 한다:
   - **보완하기 (추천)** — 기존 파일은 두고 빠진 부분만 추가/이어쓰기
   - **처음부터** — 백업 안내 후 새로 구성 (기존 파일은 `.bak`으로 보존)
   - **특정 부분만** — 어떤 영역(CLAUDE.md/권한·훅/규칙/에이전트·스킬)을 손댈지 다음에 고름
   기존 설정이 **없으면** 바로 Step 1로 간다.

> 핵심: 사용자의 기존 작업을 말없이 날리지 않는다. 의심스러우면 보존하고 물어본다.

### Step 1 · 프로젝트 자동 파악 + 확인

1. 프로젝트 루트의 신호 파일을 읽어 스택과 명령을 **추론**한다:
   `package.json`(scripts·deps) · `go.mod` · `pyproject.toml`/`requirements.txt` · `Cargo.toml` · `pom.xml`/`build.gradle` · `Gemfile` 등.
2. 추론 결과(언어/프레임워크, build·test·lint 명령, 포매터 유무)를 **요약해 보여주고** `AskUserQuestion`으로 "이게 맞나요?"를 확인한다. 틀렸으면 직접 고르거나 입력하게 한다.
3. 신호 파일이 없으면(빈 프로젝트) 언어/유형을 다지선다로 묻는다.

> 추론 규칙과 명령 매핑 표는 `references/question-flow.md`의 "프로젝트 감지" 절을 따른다.

### Step 2 · 깊이 선택 — 적응형의 핵심

`AskUserQuestion`으로 어디까지 만들지 고르게 한다. 이 선택이 이후 단계의 분기를 결정한다:

| 선택 | 생성물 | 적합 |
|------|--------|------|
| **기본 (추천)** | `CLAUDE.md` + `.claude/settings.json`(권한) | 가장 빠르게 시작 |
| **표준** | 기본 + `.claude/rules/*.md` | 규칙을 주제별로 나눠 관리 |
| **확장** | 표준 + 스타터 `agents/`·`skills/` | 코드 리뷰 등 자동화까지 맛보기 |

`$ARGUMENTS`에 `빠른`/`기본`/`표준`/`확장`이 들어오면 이 질문을 건너뛰고 해당 깊이로 진행한다. `빠른`은 **기본** 깊이로 가되, 후속 질문을 생략하고 감지값을 자동 채택하며 Step 5 최종 확인만 1회 받는다.

### Step 3 · 핵심 설정 수집

깊이에 따라 필요한 항목만 `AskUserQuestion`으로 묻는다. 자세한 질문문·선택지는 `references/question-flow.md`를 따른다.

- **명령어 확인** (모든 깊이): Step 1에서 감지한 build·test·lint 명령을 확인. 이 명령들은 권한 자동 허용과 CLAUDE.md "Commands" 절에 쓰인다.
- **코드 컨벤션** (표준·확장): 언어 strict 여부, export 스타일, 테스트 파일 위치 등 **가벼운** 다지선다 몇 개. 깊이 들어가지 않는다.
- **권한** (모든 깊이): 자주 쓰는 안전 명령(test·lint·build 등)을 자동 허용할지, 위험 명령(`rm -rf`, force push 등)을 차단할지 확인. 기본은 둘 다 "예(추천)".
- **자동 포맷 훅** (포매터 감지 시에만): "파일 편집 후 자동으로 포매터를 돌릴까요?" 예/아니오. 훅이 무엇인지 한 줄 설명을 곁들인다.

### Step 4 · (확장 선택 시) 스타터 에이전트·스킬

확장 깊이일 때만 진행한다. `AskUserQuestion`으로 원하는 스타터를 고르게 한다:
- 읽기 전용 **`code-reviewer`** 에이전트 (정의 템플릿: `references/templates.md`)
- 간단한 **스타터 스킬** 1개 (예: 프로젝트에 맞춘 `/run-checks`)

원치 않으면 건너뛴다. 스타터는 "예시이자 출발점"이며 나중에 사용자가 직접 늘릴 수 있음을 알린다.

### Step 5 · 미리보기 + 최종 확인

1. 생성/수정될 **파일 트리**와 각 파일의 핵심 내용 미리보기를 보여준다.
2. 기존 파일을 보완하는 경우, **무엇이 추가되는지**(diff 느낌)를 명확히 보여준다.
3. `AskUserQuestion`으로 "이대로 만들까요? / 일부 수정 / 취소"를 받는다. 수정 요청 시 해당 Step으로 돌아간다.

### Step 6 · 생성

확인을 받은 뒤에만 파일을 쓴다. `references/templates.md`의 템플릿에 Step 1~4에서 모은 값을 채워 생성한다.

- **생성/수정 파일**: `CLAUDE.md`, `.claude/settings.json`, (표준+) `.claude/rules/*.md`, (확장+) `.claude/agents/*.md`·`.claude/skills/*/SKILL.md`.
- 각 파일 상단/요소에 **초보자용 주석**을 넣어, 나중에 열어봤을 때 스스로 이해하도록 한다.
- 기존 파일은 **덮어쓰지 말고** 빠진 절만 이어쓴다. JSON(`settings.json`)은 기존 키를 보존하며 병합한다.
- `settings.json`의 `permissions.allow`/`deny`는 배열 병합이므로, 기존 항목을 지우지 않고 합친다.

### Step 7 · 설명 + 다음 단계

생성 후, 쉬운 한국어로 마무리한다:
- 만든 파일 각각이 **무슨 역할**이고 **언제 로드**되는지 한 줄씩.
- 편집 방법 안내: `CLAUDE.md`는 `/memory`로 열어 수정, 권한·훅은 `/config` 또는 `.claude/settings.json`을 직접 편집, 규칙은 `.claude/rules/`의 파일을 직접 편집(평범한 마크다운이다).
- "다음에 더 필요하면 `/setup-harness`를 다시 부르면 빠진 부분만 보완한다"고 안내.
- 새 세션에서 설정이 적용되려면 재시작이 필요할 수 있음을 알린다.

> 이 위저드는 단독으로 동작한다. 다른 플러그인이나 고급 에이전트 팀 구성으로 사용자를 떠밀지 않는다.

## 참조 파일 (필요할 때만 읽는다)

- `references/question-flow.md` — 각 Step의 질문문·선택지·깊이별 분기 매트릭스·프로젝트 감지 규칙. **위저드 진행 중 항상 곁에 두고 따른다.**
- `references/templates.md` — 생성할 파일들의 템플릿(CLAUDE.md, rules, settings.json, 스타터 에이전트/스킬). **Step 6 생성 직전에 읽는다.**
- `references/concepts.md` — 초보자 용어집. **사용자가 개념을 물을 때 읽고 쉽게 풀어 설명한다.**

## 테스트 시나리오

- **정상 흐름:** 빈 Node 프로젝트 → `/setup-harness` → 스택 감지 확인 → 깊이 "표준" → 명령/컨벤션/권한 확인 → 미리보기 승인 → `CLAUDE.md` + `.claude/settings.json` + `.claude/rules/*.md` 생성 → 설명.
- **기존 설정 보완:** `CLAUDE.md`가 이미 있는 프로젝트 → Step 0에서 "보완하기" → 기존 내용 보존하고 빠진 "Commands" 절만 추가 → 미리보기에 추가분만 표시.
